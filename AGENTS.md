# Инструкции для работы с CompactLoader

## Контекст

- Перед изменениями прочитай `README.md`: там описаны поведение, ограничения методов и команды проверки.
- Проект — C# / WPF, .NET 10, Windows, архитектуры x64 и x86. Целевая ОС — Windows 11; описанные в README проверки проводились на Windows 10 (19045). Не заявляй совместимость без проверки.
- Сохраняй компактность приложения: стандартный WPF, без сторонних NuGet-зависимостей и UI-пакетов без необходимости.
- Общайся с пользователем по-русски. Следуй стилю существующего кода и сохраняй пространство имён `CompactLoader`.

## Структура и изменения

- `Views/` — разметка и обработчики окна; `Presentation/` — оформление, настройки и представление процессов.
- `Themes/` — палитры и общие стили; используй ресурсы темы, общий `UiFont` и существующие механизмы акцента вместо жёстко заданных цветов и шрифтов.
- `Services/` — каталог процессов, проверки и выбор метода; `Loading/` — методы загрузки и работа с PE; `Interop/` — WinAPI и контексты потоков; `Models/` — модели.
- `Tests/Validation/` — интеграционные проверки с собственными нативными фикстурами. `Tools/IconGenerator/` — экспорт иконки из `Assets/AppIcon.xaml`.
- Сохраняй разделение UI, сервисов и Interop. Длительные операции выполняй вне UI-потока; повторные операции загрузки должны блокироваться на время выполнения.
- Не редактируй результаты сборки в `bin/`, `obj/`, `publish/`. Не отменяй посторонние изменения пользователя.
- При изменении поведения, ограничений или команд обновляй `README.md`.

## Инварианты загрузки

- Сохраняй проверки нативного PE, DLL-флага, отсутствия CLR-заголовка, соответствия архитектур и экземпляра процесса до записи в процесс.
- Учитывай размер указателей x64/x86. Для системных экспортов сохраняй обработку forwarded exports и вычисление адреса в целевом процессе.
- Код удалённых вызовов выделяется RW, затем переводится в RX со сбросом instruction cache; данные остаются RW.
- Таймаут означает неизвестный результат: не добавляй автоматический повтор, принудительное завершение потока или освобождение памяти, которую ещё может использовать целевой процесс.
- Сохраняй проверку полного HMODULE и списка модулей там, где это применимо. Manual Map не регистрирует образ в системных списках загрузчика.
- Сохраняй явный отказ для неподдерживаемых возможностей PE и блокировку повторного Manual Map после потенциально небезопасной ошибки. Не расширяй поддержку без соответствующих проверок.
- Не добавляй скрытие, обходы защиты или обязательное повышение прав. Интеграционные проверки должны работать только с собственными процессами-фикстурами.

## Сборка и проверка

Нужен .NET 10 SDK; для запуска — Desktop Runtime соответствующей архитектуры. Trimming отключён, публикация single-file остаётся framework-dependent.

```powershell
dotnet publish .\CompactLoader.csproj -c Release -r win-x64 -p:Platform=x64 --self-contained false -o .\publish\x64
dotnet publish .\CompactLoader.csproj -c Release -r win-x86 -p:Platform=x86 --self-contained false -o .\publish\x86
```

При изменениях загрузки, PE или Interop проверь обе затронутые архитектуры интеграционными проверками:

```powershell
dotnet run --project Tests/Validation/Validation.csproj --runtime win-x64 -p:Platform=x64
dotnet build Tests/Validation/Validation.csproj --runtime win-x86 -p:Platform=x86
& "C:/Program Files (x86)/dotnet/dotnet.exe" Tests/Validation/bin/x86/Debug/net10.0-windows/win-x86/Validation.dll
```

При изменениях интерфейса проверь сборку и, если доступен запуск, обе темы, акценты, масштабирование/прокрутку, выбор процесса, горячие клавиши и раскрытие журнала. Для правок только документации сборка не требуется.

В отчёте кратко укажи изменения, фактически выполненные проверки и оставшиеся ограничения. Не выдавай непройденные проверки за успешные.
